# Graphics editor edits stay pending, complete and correct

## Why

ARCHITECTURE §1 promises a 1.0 that never loses work and never corrupts a ROM, and §4 says pending graphics edits live on a cloned working arranger until Save ("anything that mutates a shared codec must clone it first"). Reading the code confirms that the graphics editor breaks this in several places. Each claim below was checked against the code; none was reproduced in the running app.

- **[LIB-ARRANGERS, UI-ARRANGING] Apply Palette leaks into the project before Save (1.0).** `ScatteredArranger.CloneArrangerCore` copies elements with `WithLocation`, so the working arranger shares codec instances with the project arranger, and `IndexedImageExtensions.TrySetPalette` assigns `codec.Palette` in place. Apply Palette therefore changes the project arranger at once, and Discard does not undo it. The leak is wider than the backlog line says. `ElementCopy` and `ElementCopier` also share codecs, so pasted elements share codecs with the arranger they came from. "Add as New Scattered Arranger..." from a sequential editor creates an arranger whose elements all share the sequential arranger's single `ActiveCodec`, so Apply Palette on one of its elements recolors all of them and the sequential view too.
- **[UI-GRAPHICS-EDITOR] Save after Resize Arranger (1.0).** `SaveChangesInternalAsync` writes the pixels, then copies the working arranger's cells into the project arranger, which was never resized. A larger working arranger fails at `SetElement` (`Guard.IsInRange(x, 0, Width + 1)` lets x == Width through to an `IndexOutOfRangeException`) after the pixels are already written. A smaller one leaves the project arranger at its old size with its old outer cells.
- **[UI-GRAPHICS-EDITOR] Navigation in Draw mode on a sequential arranger (1.0).** The `Move*` commands and `JumpToOffset` have no mode guard. The arrow, page, Home/End and +/− key bindings, and the window-wide J hotkey, move the arranger and re-decode it in Draw mode. This wipes the visible edits while `IsModified` stays true, and undo then replays them at the new offset.
- **[UI-DRAWING] Ctrl or Shift during a Pencil stroke (1.0).** `TryEngageModifierOverride` swaps in the temporary Color Picker even while a button is held, and `MouseUp` goes to `ResolveActiveTool()`, which is now the Color Picker, so `StopPencilDraw` never runs. The next press replaces `_activePencilHistory`, so the first stroke's pixels stay changed with no undo entry. An Apply Palette drag ended the same way is lost in the same way.
- **[UI-DRAWING] Indexed Pencil writes by color (promoted: silent ROM corruption).** `SetIndexedPixel` calls `TrySetPixel(color)`, which stores the first index with that color. Retro palettes often repeat colors, so picking index 9 when index 1 has the same color writes 1 to the ROM, and the history replays 9. The same mismatch happens without duplicate colors whenever the target element uses a different palette than the active one, because history always replays the chosen index.
- **[UI-DRAWING] Color Picker empties the active palette (promoted: a control that silently stops working).** `PickColor` sets `ActivePalette = Palettes.FirstOrDefault(...)`, which is null for an element whose palette is not listed, such as one pasted from another arranger. The swatches empty and Pencil does nothing.
- **[UI-ARRANGING] Resize dialog validation (promoted: loses work).** The dialog binds raw `TextBox`es to ints and has no `CanAccept`. A zero or negative size reaches `ScatteredArranger.Resize`, which throws out of an async command as an unhandled exception and can take the app down with every editor's unsaved work. Accepting the current size records history and marks the editor modified with nothing changed.
- **[UI-ARRANGING] Dropped pastes skip the Ctrl+V mode rules (promoted: loses work).** `ArrangerDropHandler` floats any paste the target can take, and Enter, a click outside, or Shift-drop applies it through `ApplyPaste`. That applies pixels whenever the target is not in Arrange mode on a tiled scattered arranger, including in View mode, where the next navigation key discards them. An element drop onto a sequential arranger is applied as pixels.
- **[LIB-ARRANGERS] Sequential `ActivePalette`: left out.** In the UI, every sequential arranger is built with `PaletteStore.DefaultPalette`, the same instance `CodecFactory` gives new codecs (`Bootstrapper` passes `paletteStore.DefaultPalette` to the factory). `ChangePalette` is never called (the call in `GraphicsEditorViewModel.View.cs` is commented out), and no UI path clones a sequential arranger. So `ActivePalette` always equals the elements' palette, and nothing renders or saves wrong today. The item stays in the backlog. A related gap it hides: the palette combo in a sequential editor's View mode never recolors the view. This should be logged separately.

## What

- A graphics editor's pending edits change only its working arranger. The project arranger, other arrangers, and other open editors change only when that editor saves. Discard returns the editor to the arranger as last saved, element palettes included.
- No library code changes a codec instance in place. Assigning a palette to an element gives that element a clone of its codec that carries the new palette. Clones, copies and pastes can keep sharing codecs, because no one changes a shared codec any more.
- Save makes the project arranger match the working arranger: the same size, and every cell copied, empty ones included.
- Sequential navigation (arrows, PageUp/PageDown, Home/End, +/−, Jump to Offset and J) works only in View mode, like the wheel and scrollbar already do. View mode never holds pending edits.
- While a pointer button is held, the tool that received the press receives every move and the release. Ctrl, Shift or Alt pressed mid-gesture does not switch tools until the buttons are up, so every stroke and every Apply Palette drag is recorded.
- Indexed Pencil writes the chosen index into elements on the active palette. Into an element on another palette, it writes the first index with the same color, as now. History records the index or color actually written at each pixel and replays exactly that.
- Color Picker on an element whose palette is not listed adds that palette to the editor's list and makes it active.
- The Resize dialog refuses sizes below 1, and resizing to the current size does nothing.
- A drop that would paste pixels into an editor outside Draw mode first switches that editor to Draw mode, exactly as Ctrl+V does: it shows the Save Changes prompt when modified, and a refused switch discards the drop. A pixel paste is never applied outside Draw mode.
- Unchanged: the snapshot undo model, the save-conflict prompt, read-only gating, element-paste rules in Arrange mode, the temporary modifier tools when no button is held, Pencil's color matching into other palettes, and Pick Palette's fallback to the default palette (UI-ARRANGING-034).

## Decisions

- **Copy-on-write at the mutation, not deep clones.** `TrySetPalette` takes an `ICodecFactory` and replaces the element with `element.WithCodec(clone)`, using the same `CloneCodec` plus palette assignment that `ArrangerSnapshot.Restore` already uses. This fixes every sharing path at once: editor clones, element copies, pastes, and arrangers made from sequential selections. Rejected: deep-cloning codecs in `CloneArranger`. It needs a codec factory in `ScatteredArranger`, and it leaves copies and pastes shared. Also rejected: making `IIndexedCodec.Palette` read-only, which breaks every plugin codec.
- **The §4 rule becomes "codecs are never changed in place".** ARCHITECTURE §4's parenthetical is reworded as an invariant: shared codec instances are allowed, and library code that changes an element's palette gives the element a cloned codec. Two in-place writers remain outside this change. `SequentialArranger.ChangePalette` mutates `ActiveCodec`, which element copies taken from a sequential editor share. The UI never calls it, so it is left with the excluded `ActivePalette` backlog item. `ProjectService.ApplyResourceDeletion` resets codec palettes in place. It runs only after `EditorsViewModel.ConfirmRemovalAsync` has closed or discarded the affected editors, so the in-place change reaches nothing pending. Its fix goes with its own 1.0 backlog item (it resets elements on surviving palettes too).
- **The project arranger takes the working arranger's whole grid.** A library method on `ScatteredArranger` (working name `ReplaceElements(ScatteredArranger source)`) resizes to the source's size and copies every cell, empty ones included. It fails with an argument error when the element pixel size, color type or layout differ. Save calls it after the pixel write. Rejected: resizing inline in the ViewModel, which cannot be unit tested.
- **Navigation is View-only.** Move commands, `FileOffset` changes and `JumpToOffset` get `CanExecute = IsSequentialArranger && IsViewMode`, and are re-notified on mode change like the expand/shrink commands. Leaving Draw mode already prompts Save/Discard, so View mode has nothing pending to lose. Rejected: prompting on each navigation key (keys repeat while browsing), and allowing navigation in Draw mode while unmodified (the first Pencil stroke then pins the offset with no visible reason).
- **The press owns the gesture.** Input routing records the tool that handled the press and sends it every move and the release until all buttons are up. A modifier key-down while a gesture is in progress is ignored. If the modifier is still held at the release (from the pointer event's modifiers), the temporary tool engages then. The routing (`_modifierOverrideTool`, `ResolveToolWithModifiers`, the press/release dispatch) moves into a plain class (working name `ToolInputRouter<TState>`), so it is unit tested without Avalonia (ARCHITECTURE §5). Rejected: ending the stroke when a modifier is pressed, which splits one stroke into two entries and still drops the release.
- **Pencil writes indices; history replays what was written.** Into an element whose palette is the active palette (by reference), Pencil writes the chosen index, provided it fits the codec's color depth. Into any other element it maps by exact color, as UI-DRAWING-003 does now, because the same index means a different color there. `PencilHistoryAction<TColor>` stores a value per point (point → written index or color) instead of one `PencilColor`, and `GraphicsEditHistory.Apply` replays each. Rejected: always writing the chosen index into every element, which changes the visible color in multi-palette arrangers.
- **Color Picker adds an unlisted palette.** The picked element's palette is added to `Palettes` as a `PaletteModel` sized like `InitializePalettes` sizes them (largest codec color count, at most 256), and made active. Rejected: keeping the previous palette (Pencil would then map the picked index through the wrong colors), and falling back to the default palette (wrong colors). Pick Palette's default fallback is a separate, existing decision and is not changed here.
- **Resize validation in the dialog, no-op in the editor.** The dialog uses `NumericUpDown` with `Minimum` 1 and `CanAccept` requires width and height of at least 1, following `CustomElementLayoutViewModel`. `ResizeArranger` returns without recording when the size is unchanged. No upper limit is added; none is specified anywhere.
- **Drops follow Ctrl+V.** `ApplyPaste` applies an element paste only in Arrange mode on a tiled scattered arranger, and a pixel paste only in Draw mode; otherwise it fails with a status message. In `ArrangerDropHandler.Execute`, a paste that is not an element paste in Arrange mode calls the same mode switch as `PasteFromClipboardAsync` and then re-floats the paste at the drop position, because the mode change clears the overlay. It applies the paste at once on Shift. Rejected: refusing drops outside Draw mode. Dragging from a browsing editor into a scattered arranger in Arrange mode would then silently do nothing.

## Spec changes

- **ARCHITECTURE §4:** reword the pending-edits bullet's parenthetical to "codec instances may be shared between clones, copies and pastes and are never changed in place; assigning a palette gives the element a cloned codec".
- **LIB-IMAGES:**
  - Change LIB-IMAGES-020: "When a palette is assigned at a pixel, the image shall give that element a clone of its codec carrying the palette, leaving every other element and arranger that shared the old codec unchanged."
  - Add: "When an indexed pixel is painted with an index of a source palette, the image shall store that index if the pixel's element uses that palette and the index fits the codec's color depth; otherwise it shall store the first index of the element's palette whose color equals the source palette's color at that index, and fail as LIB-IMAGES-010 does."
  - Delete the Open item "Palette assignment mutates a codec instance that a scattered clone shares…".
- **LIB-ARRANGERS:**
  - Add: "When a scattered arranger's elements are replaced from another scattered arranger, it shall take that arranger's size and every cell, empty cells included; if the element pixel size, color type or layout differ, then the call shall fail with an argument error."
  - Reword the Threading line "Codec instances are mutable and shared…" to "Codec instances are shared between clones, copies and pastes and are never changed in place by the library (LIB-IMAGES-020)."
  - Delete the Open item "A scattered clone shares codec instances with the original; palette assignment on the clone…".
  - Add an Edge case: element copies taken from a sequential arranger share its active codec.
- **UI-GRAPHICS-EDITOR:**
  - Change UI-GRAPHICS-EDITOR-017: "While the editor shows a sequential arranger in View mode, + and − … shall move …; in Draw mode the navigation keys do nothing."
  - Change UI-GRAPHICS-EDITOR-020: "… clicking it or pressing J shall open Jump to Offset while in View mode."
  - Change UI-GRAPHICS-EDITOR-032: "… then make the project arranger match the working arranger's size and every cell (LIB-ARRANGERS) and save that resource …".
  - Add an Invariant: "While in View mode the editor holds no pending edits." Reword the Invariant "the project arranger changes only on save (except Apply Palette, see Open items)" to drop the exception.
  - Delete the Open items on Draw-mode navigation and on saving after Resize Arranger.
- **UI-DRAWING:**
  - Change UI-DRAWING-003: "While the arranger is indexed, Pencil shall write the chosen index of the active palette (LIB-IMAGES painting by source palette); if the target element's palette lacks the color or maps it past the codec's range, then the pixel shall be left unchanged and the status bar shall show the reason."
  - Change UI-DRAWING-007: "… on an indexed arranger it shall also make the element's palette active, adding it to the palette list when it is not listed, and take its pixel index."
  - Change UI-DRAWING-009: append "; a modifier pressed while a pointer button is held takes effect only after all buttons are released."
  - Add: "While a pointer button is held, the editor shall send every pointer move and the release to the tool that received the press."
  - Delete Open items: the exact-color Pencil, Ctrl/Shift during a stroke, and the Color Picker null palette. Delete the Edge case "Picking a color from an element whose palette is not in the palette list leaves no active palette."
  - Extend the Decision "Temporary Color Picker on a modifier": it never interrupts a gesture in progress.
- **UI-ARRANGING:**
  - Change UI-ARRANGING-021: "When the user drops a paste that is not an element paste into Arrange mode on a tiled scattered arranger, the target shall first switch to Draw mode as Ctrl+V does (UI-DRAWING-017), discarding the drop if Draw mode cannot be entered; then with Shift held it shall apply the paste immediately, otherwise keep it floating with …".
  - Add: "The editor shall apply an element paste only in Arrange mode on a tiled scattered arranger and a pixel paste only in Draw mode; any other apply shall fail with a status message and change nothing."
  - Add: "Resize Arranger's dialog shall disable Resize while the width or height is below 1."
  - Change UI-ARRANGING-028: "When a resize to a different size is accepted, …; accepting the current size shall change nothing and record nothing."
  - Add: "If Apply Palette changes elements and the changes are then discarded, then the project arranger's element palettes shall be unchanged."
  - Change UI-ARRANGING-036: append the same mid-gesture modifier rule as UI-DRAWING-009.
  - Delete Open items: the dropped pixel paste, Apply Palette assigning on the shared codec, and the resize dialog validation.
- **UI-EDIT-HISTORY:**
  - Add: "A Pencil action shall record the index or color written at each pixel, and redo and replay shall write exactly those values."
  - Change UI-EDIT-HISTORY-008: add "… whatever modifier keys were pressed during it".
  - Reword the Decision "Snapshots store palettes separately": the reason becomes defense against codecs shared by clones; Apply Palette no longer mutates them.
  - Delete the Open item on strokes ended under a temporary Color Picker. Cut the Draw-mode navigation clause from the pixel-replay Open item (the source-change clause stays).
